# Security

- **Web pages are untrusted input.** The skill tells the agent to treat page content as data, never as instructions. The unattended adapters also limit what an agent that was fooled anyway can do.
- **Unattended runs with Claude Code** (`skills/what-changed/adapters/scheduler-cron/run-daily.sh`, which needs Claude Code 2.1.248 or later and checks the version before every run) start the agent in `uptodate/` with `--restricted`, `dontAsk` and an explicit list of allowed tools, so that it:
  - can read only the store and the skill folder, and your own Claude Code settings (allow rules, a Bash sandbox that runs commands without asking) do not apply to the run;
  - can edit only the ledgers and the digests, not `topics.yaml` (so a run cannot add hosts for the next run) and not `runs.log` (its lines come from `log_run.py`);
  - can fetch pages only from the hosts in `topics.yaml` plus the ones you list in `WHAT_CHANGED_FETCH_DOMAINS` (`*` allows any host). Pages elsewhere end up under "Could not check". The scripts refuse other hosts too, so they cannot be used to get around this. A source that redirects to another host (`example.com` → `www.example.com`) needs that host listed as well;
  - can run only four of the skill's scripts, by name, and those refuse paths outside the store.

  These limits were checked with a real `claude -p` run on 2026-10-15 (Claude Code 2.1.300): reading a file next to `uptodate/`, `cat` through Bash, fetching a host not on the list and writing outside the ledgers, digests and `runs.log` were all refused.
- **Windows** (`skills/what-changed/adapters/scheduler-windows/run-daily.ps1`, not tested yet): the same read, edit and fetch limits, and the agent gets no shell at all; the script runs the skill's scripts itself before and after the agent.
- **GitHub Actions template:** the same edit and fetch limits (set `WHAT_CHANGED_FETCH_DOMAINS` as a repository variable), no git credentials for the agent, and a separate step that commits only the store files, refuses if anything else changed, and disables git hooks. The agent can read the whole checkout, and the repository's own `.claude/settings.json` applies (the template does not use `--restricted`, which has not been tried with the action), so keep the store in a repository that holds nothing private and has no such settings. Not run on GitHub yet.
- **Other hosts** (Codex, Antigravity, Qwen Code) use their own sandbox and approval settings; the limits above are not enforced there. `run-daily.sh` refuses to run them when the skill is installed inside the project, because those hosts can write anywhere in it; for the same reason it keeps its logs and its record of the last run outside the project (`~/.local/state/what-changed/`), and `precheck`, `log_run` and the catch-up hook refuse to write through a symlink or hard link (so a store whose files are links, say into a synced folder, always goes to the agent).
- **The scripts fetch only `http(s)` URLs**, at most 5 MB per page, and never local or private addresses: the check is repeated on every redirect, and the connection goes to the address that was checked, so a name that changes its answer (DNS rebinding) cannot reach your network. Behind a proxy, the proxy resolves names instead.
- **Pinned actions.** The GitHub Actions template pins each action to a full commit SHA, so a re-pointed tag cannot swap the code that receives your API key. Update the SHAs yourself when you upgrade.
- **No unattended adapter for Gemini CLI.** Its tool permissions could not be narrowed enough for runs nobody watches, so use the skill in Gemini CLI interactively and approve tool calls yourself.
- **Not covered:** an agent fooled by a page can still write wrong claims into the ledgers and digests, which is why the checks above exist and why every claim carries its source. It can also put store contents into a URL on an allowed host, push a topic's `last_run` to today so a weekly topic waits another week, or move a claim's `review_by`. Anything you put in `CLAUDE.md` files that Claude Code loads, and the store itself, is visible to the agent. On GitHub Actions the fetch limit for the scripts relies on the action passing environment variables through to them, which has not been checked.
- **Read any third-party skill before you install it, this one included.** Skills are instructions plus scripts that run with your agent's permissions.
